# V8：沿细胞接触网络协同出芽

独立程序：`output/release-v8/细胞模拟V8.exe`。从单个细胞开始，启动暂停；点击“运行”或按空格推进。默认固定随机种子为 0。V6、V7 原程序仍保留。

## 这次改动

- 缺糖和废物压力信号沿实际接触连接逐级传播。强化运输通道具有更高的信息连接权重，信号有响应时间、衰减和糖成本，细胞保留本地信号记忆。断开接触后不能直接传信。
- 出芽由储能、健康和局部表面条件合适的细胞发起。它向邻居发送出芽信号和方向，邻居最多接力七次；成员共享本轮信号的阶段，并在自身分裂时继承局部状态。
- 细胞用有泄漏的邻居接力信号形成局部协作强度。它不是全局细胞计数；小群体没有足够的持续支持，无法立即打开分离边界。
- 细胞还沿接触传播与原组织仍有连接的信号。过早覆盖整个小组织、没有分离界面的尝试会在局部自行取消，稍后再尝试。
- 同一局部信号区域加强黏附，边界逐渐弱化；出芽方向上的缓慢移动消耗糖。程序不瞬移、不直接删除连接，也不根据全局规模或评分决定在哪切开组织。
- 候选突变在发起细胞内产生，遗传信息沿邻居接力。各细胞达到局部协作条件后自行启用；全局子团登记不再统一修改基因，也不平均重写整个团块的基因组。
- “出芽通信”和“团块谱系”是新增观察模式。选择模式会给出相关数据组合，之后仍可单独调整数据面板和糖/废物箭头。右侧数据自动按换行高度排版；镜头在培养区扩展时保持原来的观察比例，由用户缩放和拖动。

## 物理团块和谱系

谱系编号只用于记录。细胞的黏附、排斥、移动和候选基因启用均不读取谱系编号。

观察器检查实际接触图已经断开的组件，再登记子团。首轮默认记录下限为 48 个细胞，且原谱系须仍有至少 48 个细胞；这些门槛只影响登记。关闭登记或提高登记门槛不会改变细胞运动与基因变化。

同一物理团块可能有多个谱系；子团也可能再次接触和融合。因此“活跃谱系”与“细胞团数量”是两个指标，不会用谱系标签强行把它们推开。“小碎块”统计不足 48 个细胞的组件，“极小碎块”统计不足 8 个细胞的组件。

仅全部细胞死亡才重新建立下一轮创始细胞。正的时间上限也不会让 V8 提前换代。重启仍使用历史表现与遗传尝试，这是实验轮次机制。

## 首轮验证

2026-10-14：从单细胞起点运行 10 个固定种子，每种 7500 步、300 个模拟时间单位。首轮通过条件为：至少登记一个 48 细胞以上的子团、最后至少 100 个活细胞、至少 80% 的活细胞位于不小于 48 细胞的连通组件中、极小碎块占比不超过 5%、糖/废物/结构收支误差低于 `1e-7`，且没有时间换代。

结果 **8/10 通过**。实际登记的子团有 **48–204 个细胞**；各种子的极小碎块占比为 **0–3.4%**。种子 2 在观察窗内没有登记子团；种子 5 的小组件细胞占比约 24.2%，未达到大组件比例门槛。两项失败保留在结果里，不能据此承诺每个随机种子都会达到目标。

局部隔离测试证明信号每步只能跨一个接触、无法到达断开的细胞、通信与运动耗糖进入物质总账。64 细胞的接力区域在约 31.7 时间单位物理脱离，在测试结束时仍为独立组件；7 细胞对照没有打开分离边界。提高登记下限至 1000 后，运动和基因变化仍逐步完全相同，只是不登记子团。

同种子完整重复、半程保存后精确续跑、全灭才换代、原有 53 项 Python 回归测试均通过。19 种视图已作离线绘制检查，未将离线绘图耗时当作实时窗口帧率。

摘要：`docs/verification/V8.json`。完整状态、配置、图像与结果：`output/verification/native-v8/`。

## 构建与复验

使用本机已有的 MSYS2 编译器，不修改系统 PATH，不下载或安装工具：

```powershell
./native/build.ps1 -Version V8 -CompilerPath C:/msys64/ucrt64/bin/g++.exe
C:/Users/HP/anaconda3/python.exe tools/verify_native_v8.py --checks
```

局部机制测试源码是 `tools/native_cooperation_test.cpp`。程序静态链接 C++ 和线程运行库；已检查导入依赖只有 Windows 系统组件，不需要 MSYS2、Python 或 Visual Studio 随程序分发。目标为现代 64 位 Windows，尚未在其他电脑实测。

这是局部协同机制的一次扩展，尚不等于已经实现完整的宏观智能、真实器官或真实生物孢子模型。
